## Decided D22–D24 (owner, final)
**D22 — open state vs effect state (separate in code).**
- `effect`: idle | counting | exploding (v4 `done` flag, countdown, flash, canvas). `open`: boolean (list visible), independent.
- Scroll-away (v4 IO rule unchanged: `done` && not intersecting && top>0) resets `effect` only; never changes `open`; category stays open until user presses Close Category.
- Open Category opens directly, no countdown/explosion. Close Category: list hidden, Open Category shown; stops the video inside only if it is the one playing (D19).
- Cover (with burst) is shown only for a never-opened category (effect idle, open never true). Consequence (derived, confirm in checklist): after first reveal the burst does not replay in the same page session. Mid-run reset (Q1) still restores the cover, then the pending timer opens the list 2200 ms after click, as v4.
**D23 — focused-card playback.**
- Focused card auto-plays (muted) only on a focus change and only when no video is playing. Any new `play` stops the previous (v4 safety net kept). Focus change never pauses another video.
- Manual pause is sticky: per-video `userPaused` set on user pause, cleared only on user play; no auto-resume while the card stays focused or re-focuses. Programmatic pauses (safety net) must not set `userPaused` (native `pause` event does not say who caused it → programmatic-pause marker; unverified in browser).
- All D19 rules hold: one playing video globally; opening another category never stops it.
**D24 — CSS.** Verified: `verify_css` hashes the whole `globals.css` (sha256 `6e4c55d2…ff460`, 40,694 bytes), so any added rule breaks the lock; adding there is impossible without changing the lock (owner forbids).
